## 免费额度核算（关键数字）

| 资源 | 免费额度 | 我们的用量 | 结论 |
|---|---|---|---|
| GitHub Actions | 公开仓库**无限**分钟 | 每日 ~30 分钟 | 充足（仓库须为 public） |
| GitHub REST Search API | 认证后 30 次/分 | 发现任务分片 ~100-600 次/周 | 充足 |
| GitHub GraphQL API | 5000 点/小时 | 快照 6 万仓库 ≈ 600 次请求 ≈ 600+ 点/日 | 充足 |
| OpenRouter 免费模型 (`*:free`) | 每日免费请求上限（各模型不同，通常 50-1000 次/日） | 每日仅处理**新上榜**项目 ≤50 个 | 充足，有降级策略 |
| Cloudflare Pages | 带宽不限，构建 500 次/月 | 每日 1-2 次构建 | 充足 |
| Git 仓库存储 | 建议 <1GB，单文件 <100MB | 快照裁剪后 <50MB | 充足 |

## AI 分工：生成 vs 决策

| 任务 | 模型 | 成本 |
|---|---|---|
| 中文摘要、周报点评（**生成**类） | OpenRouter `:free` 模型（llama/gemma/mistral 自动降级） | $0 |
| 低置信度仓库分类（**决策**类） | Jev（TypeSafe System One，`typesafe/jev-router`），二级分类器 | $0.042/M 输入、输出 $0；全量补分类 <$1 一次性，之后每月 <$0.01 |

Jev 默认**关闭**（设置仓库 Variable `JEV_ENABLED=1` 启用）：规则引擎先跑（免费、确定性），仅残量低置信度项目交 Jev 做 Choice 决策，置信度 <0.6 仍保持不分类（宁缺毋滥）。实现见 `collector/jev_classify.py`。

## 数据流与口径

- **快照**：每日北京时间 00:30（UTC 16:30）采集全量仓库总 star，存 `data/snapshots/YYYY-MM-DD.json`（UTC 存储）。
- **净增**：周期净增 = 期末快照 − 期初快照；增长率 = 净增 / 期初 × 100%（期初为 0 或缺失显示 N/A；负增长不截断）。左闭右开区间，Asia/Shanghai 边界。
- **进行中周期**：当前日/周/月标注"进行中"，期末用最新成功快照并显示采集时间。
- **快照裁剪**：保留最近 40 天日快照 + 每月 1 日月度快照永久存档；其余由 workflow 自动删除（幂等）。
- **仓库元数据**：`data/repos.json`（发现结果 + 分类 + 标签 + 置信度 + 分类版本）。
- **摘要**：`data/summaries.json`，按仓库幂等生成，不重复消耗 OpenRouter 额度。

## 降级与故障策略

| 故障 | 行为 |
|---|---|
| GitHub API 限流 | 指数退避重试；当次任务失败则不写快照，榜单标注"数据缺失"而非编造 |
| OpenRouter 额度耗尽 | 跳过摘要生成，展示原文描述 + "摘要待生成"，下日补跑 |
| 某日快照缺失 | 跨缺口的周期榜标记"覆盖不足"，不显示伪精确净增 |
| Actions  cron 延迟 | 快照文件记录实际采集时间戳，界面如实显示 |

## 密钥管理（全部走 GitHub Secrets）

- `GITHUB_TOKEN`：Actions 自动注入，无需创建。
- `OPENROUTER_API_KEY`：用户已有，加入仓库 Secrets。
- `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID`：部署用，见 deployment.md。

任何密钥不进入代码、不进入前端 bundle；AI 调用全部发生在 Actions 服务端。

## 为什么不用数据库

Supabase/Neon 免费层有休眠与额度限制，Cloudflare D1 免费层够用但增加复杂度。榜单数据本质是**每日批量生成的只读快照**，git + 静态 JSON 是最稳的免费方案：天然版本化、可回滚、可审计、可本地复现。当日均请求量超过静态站能承载时再迁移 D1，迁移路径已预留（JSON schema 即表结构）。
